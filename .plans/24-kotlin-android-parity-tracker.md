# Kotlin Android parity tracker

> **Status:** the demo gateway is gone. Every screen reads the live
> `LiveWorkspaceGateway` over the WebSocket transport, and S5 Connect sign-in is
> Clerk's Android SDK (`cloud/CloudAuth.kt`). S5 Connect now goes further than
> sign-in: DPoP proofs, the relay token exchange, managed environment discovery,
> and proof-bound per-connection authorization are implemented
> (`cloud/Dpop.kt`, `cloud/RelayClient.kt`, `cloud/RelayEnvironmentAuthorizer.kt`,
> `cloud/CloudEnvironments.kt`). QR pairing, image and web previews, deep links,
> the sharesheet, launcher shortcuts, durable drafts, FCM/Relay registration,
> alert rendering, and Android 16 Live Updates are real. FCM runtime delivery is
> configuration-gated: source builds without a Firebase client entry for
> `club.touchtech.s5code.kotlin` report that honestly instead of borrowing the RN
> app's identity. Glance remains unavailable. Rows below are marked against live
> behavior only.
>
> **Verified 2026-08-30:** `:app:assembleDebug`, `:app:lintDebug` (strict,
> zero errors), and `:app:testDebugUnitTest` all passed. The unit gate ran 418 JVM
> tests with zero failures (one skipped by design, below). Lint reported zero
> errors or warnings (four informational hints). The skipped test is a
> live-server contract sweep (`transport/LiveServerContractTest.kt`) that runs
> against a real `node apps/server/src/bin.ts serve` seeded from a copy of real
> data, and decodes every payload this client reads: descriptor, token exchange,
> session, socket ticket, `server.getConfig`, shell snapshot, five thread detail
> snapshots, file entries, git status and refs, review preview, filesystem browse,
> usage, and the terminal attach stream plus its write/resize/close calls. It is
> skipped without `T3_LIVE_HTTP`/`T3_LIVE_TOKEN`,
> so a normal run stays hermetic. Not verified: anything needing a device or
> emulator (Keystore, camera, WebView, Clerk sign-in), and the relay round trip,
> which needs a signed-in account.
>
> **Why that test exists.** Three bugs shipped in builds whose unit tests were all
> green, because the fixtures were written from the same wrong assumption as the
> code: a DPoP proof header missing its two fixed JWK members, `platform` typed as
> a string when the contract has it as a struct, and `/api/auth/session` sent as a
> `POST` when the contract defines a `GET`. Each produced a confident, misleading
> error on a device ("proof key rejected", "not an S5 Code server") and none was
> reachable from a hand-written fixture. Decoders are now checked against a server
> that speaks the contract.

This is the implementation checklist for the native Kotlin/Jetpack Compose client described in `.plans/23-kotlin-android-native.md`.

Material 3 Expressive is mandatory for every user-visible destination. A row cannot be marked complete merely because it inherits `MaterialExpressiveTheme`: its hero action, action sizing, component selection, color/containment, typography, shape/state treatment, motion/reduced-motion behavior, and accessibility must pass the expressive audit below. Official Compose Material 3 APIs take precedence over reproducing React Native or SwiftUI chrome.

Sources are deduplicated from:

- **RN:** current React Native client under `apps/mobile`;
- **Swift:** native SwiftUI client in [PR #5178](https://github.com/pingdotgg/t3code/pull/5178).

Status key:

- `[ ]` not implemented or not verified;
- `[x]` implemented and verified in Kotlin;
- `N/A` may only be used with a written Android-specific reason and maintainer approval.

For each completed row, append the Kotlin source/test reference in the Notes column. A page is not complete until its loading, empty, error, offline/stale, accessibility, adaptive-layout, and Material 3 Expressive audit states are covered.

## Cross-cutting interaction parity delivered

- `design/component/LoadingStrip.kt` is mounted by `S5Screen` for in-place reads and mutations instead of replacing content with a blocking spinner.
- `ActionProgressOverlay.kt` is app-scoped, survives navigation, auto-dismisses terminal states after four seconds without dismissing a newer action, links to a created PR when the contract supplies one, and emits success/failure haptics. `GlobalErrorBanner.kt` provides one manually dismissible, six-second transient failure surface above navigation.
- `ConfirmDialog.kt` centralizes destructive confirmation for thread deletion, environment removal, rewind, and per-category/all cache clearing. Home, Archive, thread feed, branch, and PR lazy rows use stable `animateItem` placement/enter/exit motion; fold groups use explicit expand/shrink/fade transitions.
- Clipboard, pull-to-refresh threshold/completion, swipe threshold/action, and operation completion all use Android haptic semantics; there are no continuous vibration or per-frame animation loops.

## Explicit Android equivalents / non-equivalents

These are deduplication decisions, not completed items:

- iOS **Live Activities/Dynamic Island** maps to Android 16 **Live Updates** with an ongoing-notification fallback.
- WidgetKit recent-task/agent widgets map to **Jetpack Glance** widgets.
- Siri/App Intents map to Android **launcher shortcuts** and app/deep links; voice-assistant integration is not required unless separately requested.
- iOS Share extension maps to Android **Sharesheet intent filters/activity handoff**.
- Keychain maps to **Android Keystore-backed encrypted storage**.
- iOS glass navigation styling does not carry over; use **Material 3 Expressive** components and Android adaptive navigation while preserving layout hierarchy and content.
- APNs maps to **FCM**. Notification semantics, dedupe, freshness and destination routing must remain equivalent.
- iOS background refresh maps to lifecycle/network-aware reconciliation and constrained **WorkManager** jobs only where deferrable work is useful.
